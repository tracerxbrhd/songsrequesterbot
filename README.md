# 🎵 Songs Requester — Яндекс Музыка

Личный Telegram-бот на **Telegram Cloud Serverless**. Единственный источник — **Яндекс Музыка**. Поддерживаются ссылки на отдельные композиции, поиск по названию и попытка отправки доступного незашифрованного MP3.

**Не универсальный загрузчик:** Яндекс использует неофициальный API, который может отказывать в выдаче MP3 даже авторизованному пользователю. Офлайн-музыка в приложении не тождественна открытым MP3. Бот не расшифровывает DRM/encraw и не обходит запреты API.

## Возможности

- Ссылки вроде https://music.yandex.ru/album/31348570/track/126278860 и https://music.yandex.ru/track/126278860.
- Поиск по названию/исполнителю; карточки с альбомом и ссылкой на оригинал.
- Кнопка «⬇️ Скачать MP3» запрашивает raw MP3 и отправляет через Telegram, только если файл действительно доступен и Telegram принимает HTTPS-ссылку.
- SQLite-кеш Telegram file_id для повторных отправок.
- Команды /start, /help, /status, /diagnose, /search, /id, /privacy, /delete.
- Доступ ограничен владельцем в BotFather. Дополнительная регистрация не нужна.

Другие музыкальные сервисы удалены из кода, интерфейса и настроек.

## Причины прошлых ошибок

В ранней реализации для метаданных ошибочно использовался **GET /tracks/{id}**. Текущий клиент MarshalX использует **POST /tracks** с телом типа application/x-www-form-urlencoded и параметром track-ids. Это исправлено.

Раньше ответы с HTTP 405/451 и некоторыми другими статусами сворачивались в общий код HTTP 4XX. Теперь /diagnose показывает **точный код HTTP 400–599**, не читая и не публикуя тело ответа. Это позволяет отличить отказ по методу (405), региональное/правовое ограничение (451) и другие случаи.

Диагностика /diagnose выполняет четыре проверки: действительность OAuth по наличию account.uid в ответе /account/status (сам UID не показывается), получение тестового трека (POST /tracks), поиск «Монеточка» (GET /search) и проверку MP3 (GET /get-file-info). Каждая показывает **точный код HTTP**, без данных аккаунта, токена, заголовков, содержимого ответа и временных аудиоссылок.

**HTTP 403 на MP3** означает отказ сервера в этой операции. Он сам по себе не означает, что OAuth недействителен. Возможны ограничения доступа к файлу или формату; нельзя гарантировать, что Яндекс разрешит выдачу выбранного трека.

## Настройка

В GitHub → Settings → Secrets and variables → Actions добавляются два секрета:

| Secret | Назначение |
| --- | --- |
| TGCLOUD_TOKEN | BotFather → Serverless → CLI Access |
| YANDEX_OAUTH_TOKEN | Личный OAuth Яндекс Музыки через Device Flow |

Получение OAuth описано в [документации MarshalX](https://ym.marshal.dev/token/). Не отправляй токен в чат, issues или комментарии. Во время GitHub Actions из него генерируется исключённый из Git модуль tgcloud/lib/runtime-secrets.js. Он доступен редакторам Cloud-проекта, поэтому не выдавай им доступ.

После мерджа в main workflow запускает проверки → tgcloud fetch → tgcloud push → tgcloud migrate --safe → tgcloud webhook sync.

## Проверка после деплоя

1. Напиши /status — он проверяет только наличие OAuth.
2. Напиши /diagnose и посмотри результаты всех четырёх запросов.
3. Отправь ссылку на композицию либо запрос «Монеточка Монополия».
4. После появления карточки нажми «⬇️ Скачать MP3».
5. Если получен 403, это ограничение доступа Яндекса; если Telegram не смог взять файл по URL, бот скажет об этом отдельно.

## Технические детали

- Telegram Cloud Serverless: JavaScript, sdk, SQLite; нет runtime Node/npm, FFmpeg, URL/URLSearchParams/TextEncoder.
- Метаданные: POST /tracks с track-ids, используя документированный fetch.body.form() в Telegram Cloud SDK (с безопасным запасным вариантом). Поиск: GET /search.
- Файл: подписанный GET /get-file-info, codec=mp3 и transport=raw.
- Аудио передаётся только как проверенный краткоживущий HTTPS URL для Telegram Bot API. Текстовый sdk.fetch не используется для бинарной загрузки.
- Отсутствует поддержка FLAC/DRM, альбомов, плейлистов и прочих площадок.

Локальная проверка с Node.js 22+:

~~~sh
npm install --no-audit --no-fund
npm run check
npm test
~~~

Проверки CI не гарантируют, что Яндекс разрешит реальную загрузку. После изменения API потребуется живой smoke-test.

Источники: [MarshalX/yandex-music-api](https://github.com/MarshalX/yandex-music-api), [Telegram Cloud Serverless](https://blogfork.telegram.org/bots/serverless).


## Важное различие в диагностике

- **HTTP 405**: запрос с таким методом не поддерживается обработчиком API. Проверить совпадение HTTP-метода и endpoint.
- **HTTP 451**: возможен отказ по юридическим/региональным причинам. Telegram Cloud имеет собственное сетевое расположение; успешный вход в Яндекс с телефона не доказывает доступность API из облака.
- **HTTP 403** на get-file-info: сервер отказал в выдаче аудио. Сам по себе успешный account/status не гарантирует разрешения на скачивание.
- **HTTP 429**: превышен лимит запросов; не продолжать частые попытки.

Если после деплоя поиск и трек возвращают 451 или другие ограничения со стороны сервера, дальнейшее редактирование JavaScript не снимет запрет. Не следует повторять запросы агрессивно или пытаться обходить отказ. Сообщи только четыре строки /diagnose.
